# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Releases are tagged `notion-skills--v<version>` (the naming `claude plugin tag`
expects). See [CONTRIBUTING.md](CONTRIBUTING.md#releasing) for the release steps.

## [0.3.1] — 2026-08-22

Positioning only — no behaviour change, no code touched.

### Changed

- The plugin description now leads with what this does that Notion's own skill
  install does not: no per-skill install step, and no local copy of the skill.
  It still names the SessionStart hook and states that the plugin reads Notion
  with the user's own credentials and sends no telemetry.
- README opens with a section comparing this to Notion's built-in install, which
  saves a skill page to your computer for Claude Code, Codex, Cursor, Gemini and
  Grok. That is first-party, covers more agents and carries attached files, so
  the section says plainly to use it if it covers you, and describes the trade
  this plugin makes instead.

## [0.3.0] — 2026-08-22

First tagged release. Setup went from a sequence of model-driven steps to a
single command, and the MCP transport became a real code path instead of a
hand-written one.

### Added

- `scripts/setup.mjs` — one command resolves the data source, checks the schema,
  writes the config and runs the first sync. The `setup` skill used to walk the
  model through those as separate tool calls; each was a round trip for work that
  is entirely deterministic. Measured end to end against a local 66-row fixture:
  **117–134 ms** for the whole thing.
- `--from-json <file|->` on `sync.mjs` and `setup.mjs`. A script cannot call an
  MCP server, so the model fetches the rows and hands them over; every transport
  then shares one filter/render/write implementation.
- `--property key=name` on `setup.mjs`, so a database with non-default column
  names (a Japanese schema, say) is configured in the same single command.
- `--transport`, `--injection`, `--ttl-hours`, `--exclude-page`, `--dry-run` and
  `--json` on `setup.mjs`.
- A test suite (`node --test tests/*.test.mjs`) and CI across Node 18/20/22.
  There was none before; it needs no dependencies and makes no network calls.

### Fixed

- **The documented MCP query returned no page IDs.** `skills/sync/SKILL.md`,
  `skills/notion-skill-router/SKILL.md` and the skill generated by
  `scripts/build-web-skill.mjs` all selected the `Name`, `Trigger`, `Status`,
  `Category` and `Runtime` columns — and no `id` column. The registry format is
  keyed by page ID, and the generated web skill went on to say "exclude by id",
  "link as `notion.so/<page_id>`" and "fetch the page by its id from the query".
  All three now ask for `id`, and a test asserts every shipped query does.
- **`config.transport` was documented but never read.** `notion.mjs` chose its
  transport purely from whether `NOTION_API_TOKEN` was set, so `"transport":
  "ntn"` silently used the env-var path anyway. The setting is now honoured, and
  an explicit choice fails with a reason instead of falling back to a different
  transport than the one asked for.
- Rows with no page ID are now a hard error rather than being skipped. A registry
  that is merely *short* is indistinguishable from a correct one, and the missing
  skills just stop routing.
- A partial result (`has_more: true`) handed to `--from-json` is refused for the
  same reason.

Found by automated review on this change, before release:

- The data-source probe walked the entire store. `resolveDataSourceId` asked "is
  this id a data source?" via the fetch-everything helper with `page_size: 1`,
  which follows every cursor — 66 requests against a 66-row database, on the code
  path whose purpose is making setup fast. `probeDataSource` makes exactly one.
- A database with several data sources silently got the first one. If the skills
  table was not first, setup synced the wrong table and every later error
  described a database the user never chose. It now lists the sources and asks.
- A non-404 database lookup failure was treated as "maybe it is a data source
  id" and retried, so an auth, permission, rate-limit or outage error was
  replaced by a second, misleading one. Only not-found falls through now.
- `--data-source-id` accepted anything on the `--from-json` path, since the first
  registry builds from the supplied rows and nothing validates the id until the
  next sync. It is now parsed like every other id argument.
- A pinned `--transport token`/`ntn` was not checked when `--from-json` was
  present: setup succeeded with no token, reported `mcp`, and wrote `"token"` to
  config — a configuration that could not work on the next sync. The pin is now
  validated whether or not rows are supplied, and the reported transport is
  asserted to match the one written.

### Changed

- The `setup` skill reports counts, categories and runtimes instead of re-listing
  every skill. On a 66-skill store the summary is ~340 bytes where the registry
  is ~9 KB; re-emitting it as a linked table spent a slow turn on information
  already visible in Notion.
- `plugin.json`'s description now names the SessionStart hook and states that
  syncing calls the Notion API with the user's own credentials, with no other
  network access and no telemetry.

### Note on versioning

Everything between `827ad3e` and `e692132` — `excluded_pages`, the claude.ai web
variant, and its redesign from a frozen skill list to a live query — shipped
under the version string `0.2.0`, because no release was ever tagged and the
marketplace served the branch head. Those changes are listed under 0.2.0 below,
where they were written, but 0.3.0 is the first version a user can actually pin.

## [0.2.0] — 2026-07-25

### Added

- `Runtime` property (`any` / `claude-code` / `notion`), making the store
  agent-agnostic: Notion AI can skip skills that need Claude Code's local tools
  (`b39850f`).
- `excluded_pages` in the config, to keep reference pages and superseded
  duplicates that live in the same database out of the registry (`827ad3e`).
- A standalone router skill for environments without hooks — claude.ai — built by
  `scripts/build-web-skill.mjs` (`b0c33d1`), exposed as the `web-skill` plugin
  skill (`6e18216`).

### Changed

- The web variant stopped enumerating skills and now queries the database live at
  request time (`e692132`). Enumerating meant fighting claude.ai's 1024-character
  description limit, splitting across files, and rebuilding on every change — and
  a hand-built list had already dropped a skill (`fc3695e`).

### Fixed

- README inaccuracies found in review: broken links, claims that did not match
  the implementation, missing sections (`ed4f3ae`).

## [0.1.0] — 2026-07-22

### Added

- Initial release (`a4bca90`): a Notion database as an auto-syncing skill store
  for Claude Code — the SessionStart hook, the registry cache, the sync script
  with token and `ntn` transports, and the router and creator skills.
